# 赛智通验收与演示指南

更新日期：2026-08-05

用途：项目内部预验收、课程答辩和正式验收前检查

## 1. 验收前准备

### 环境

- Python 3.11 独立虚拟环境；
- Node.js 20；
- 已执行最新迁移的 Supabase；
- 有效的 DeepSeek API Key；
- 正确的 GitHub Actions Token 和刷新工作流权限；
- Render `ALLOWED_ORIGINS` 与真实前端域名一致。

### 数据

- 竞赛库至少有 10 条未过期记录；
- 至少覆盖 2 个数据来源和 3 个类别；
- 每条演示数据尽量包含官网、主办方、报名截止时间和摘要；
- 不使用真实学生的身份证号、密码或其他敏感数据。

## 2. 验收前命令

```powershell
python -m pytest tests -q -p no:cacheprovider

Set-Location frontend
npm install
npm run build
```

启动后端：

```powershell
uvicorn api:app --host 0.0.0.0 --port 8000
```

启动前端：

```powershell
Set-Location frontend
$env:VITE_API_BASE_URL="http://localhost:8000"
npm run dev
```

基础检查：

- `GET /` 返回 200；
- `/docs` 可以打开；
- `GET /api/competitions` 返回 200 且包含竞赛；
- 浏览器控制台没有 CORS 错误；
- 页面没有密钥、SQL 或 traceback。

## 3. 推荐演示脚本

### 场景一：新用户推荐

用户：

> 我是计算机专业大三学生，擅长 Python 和机器学习，想参加国家级人工智能竞赛，每周可以准备 8 小时。

预期：

- 系统识别专业、年级、技能、方向、级别和时间；
- 信息足够时不重复追问；
- 返回真实数据库中的推荐；
- 每个推荐包含适配理由、风险或待确认事项；
- 过期竞赛不应作为主推荐。

### 场景二：上下文追问

用户：

> 详细介绍第二个。

预期：

- 系统正确引用本轮第二个推荐；
- 返回主办方、时间、官网、简介和待核实项；
- 不重新执行一遍推荐，也不询问“第二个是什么”。

### 场景三：材料生成

用户：

> 给第二个竞赛生成一份报名个人简历。

预期：

- 正确继承目标竞赛；
- 缺少必要信息时进行有限追问；
- 生成可下载 `.docx`；
- 文件名与竞赛及材料类型对应；
- 明确说明材料是初稿，需要人工复核。

### 场景四：竞赛库和收藏

操作：

1. 打开竞赛库并筛选类别；
2. 打开竞赛详情或官网；
3. 登录后收藏一项竞赛；
4. 在“我的竞赛”查看；
5. 取消收藏。

预期：列表、详情和收藏状态一致，刷新页面后状态按产品设计保留。

### 场景五：会话恢复

操作：

1. 登录用户完成两轮推荐对话；
2. 创建或保存会话；
3. 刷新页面或重新登录；
4. 打开历史会话并继续追问。

预期：消息、画像和最近推荐上下文可以恢复。

### 场景六：数据刷新

操作：管理员或允许的用户触发竞赛库刷新，并查看状态。

预期：

- API 返回 202，而不是同步等待爬虫结束；
- GitHub Actions 收到任务；
- 状态从 queued/running 更新为 completed、partial 或 failed；
- 新增、变化、未变化、抽取失败和删除数量合理；
- 单一来源失败不会抹掉其他来源旧数据。

## 4. 异常场景

验收人员建议主动测试：

- 输入与竞赛无关的问题；
- 不配置或临时断开 LLM；
- 数据库暂时不可用；
- 竞赛库没有候选记录；
- 生成材料时信息不足；
- 登录密码错误；
- 普通用户访问管理员接口；
- 重复点击刷新按钮；
- 官网字段缺失或日期无法确认。

系统应给出清楚、可行动的提示，不得显示内部堆栈或伪造结果。

## 5. 模拟验收问答

**问：系统解决什么问题？**

答：它帮助大学生从分散竞赛信息中找到更符合自身背景的项目，并把信息理解、推荐和材料准备串成连续对话流程。

**问：为什么采用多 Agent？**

答：采集、抽取、推荐和材料生成的数据结构、失败方式和测试重点不同。MainAgent 负责上下文和调度，业务 Agent 各自处理清晰职责，便于替换、降级和验证。

**问：推荐是否由大模型随意生成？**

答：推荐候选来自 Supabase 中的结构化竞赛记录，先经过硬性条件和规则筛选，再结合画像排序和解释。官网仍是最终权威来源。

**问：用户聊天时是否现场爬网页？**

答：正常生产流程不会。采集由独立 GitHub Actions 刷新任务完成，在线推荐直接读取已经处理的数据。

**问：没有 LLM 是否还能工作？**

答：部分意图识别、规则筛选和基础字段处理可以降级运行，但复杂通知理解、自然语言效果和材料质量会下降。

**问：材料能否直接提交？**

答：不能承诺。系统生成的是可编辑初稿，用户必须根据学校和赛事模板人工复核。

**问：如何保护用户数据？**

答：密码使用哈希存储，接口采用 JWT，服务端密钥不进入前端，管理接口需要角色校验。公开演示不应输入敏感个人信息。

**问：当前是否已经正式验收就绪？**

答：截至 2026-08-05，只适合内部预验收。数据库迁移、CORS 和失败测试修复后，需要再执行一次真实环境端到端验收。
